# 心理岛屿测评站 · 微信小程序改造说明

> 版本：v1.0（2026-10-10）
> 适用范围：本项目（`psy-test/` 静态多页测评站）如需迁移为微信小程序时的注意事项。

---

## 1. 背景与结论

当前测评站是 **React（纯 JS、无构建工具）+ 自定义 CSS** 的静态网页，部署在 GitHub Pages。

**结论先行：微信小程序不能直接运行网页版 React，需要通过适配框架（推荐 Taro）改造。改造时逻辑层（题目、计分、结果计算）可以直接复用，界面层（组件、样式）需要重写。**

---

## 2. 为什么网页 React 不能直接用在小程序

| 维度 | 网页（当前项目） | 微信小程序 |
|---|---|---|
| 运行环境 | 浏览器（有 DOM） | 微信自研渲染层（无 DOM） |
| 界面语言 | HTML + CSS + React | WXML + WXSS + JS |
| React 支持 | 直接运行 | 不能直接运行，需编译转换 |

类比：网页 React 是「乐高说明书」，小程序是「另一种积木品牌」，图纸不能直接套，但「拼积木的思路」通用。

**React 的核心概念（组件、状态、数据驱动界面）在小程序开发中完全通用**，只是需要一层「翻译器」。

---

## 3. 三条技术路线对比

| 方案 | 开发语言 | 适合谁 | 优点 | 缺点 |
|---|---|---|---|---|
| 原生小程序 | WXML + WXSS + JS（微信语法） | 只做小程序、不想引入框架 | 最直接、无框架负担 | 代码无法复用到 H5/App |
| **Taro**（京东开源） | **React 语法** | 会 React 的团队（本项目） | 用 React 写 → 编译成小程序；一套代码可出微信/支付宝/百度/H5 | 需要学习 Taro 约定；工程化配置 |
| **uni-app**（DCloud） | **Vue 语法** | 会 Vue 的团队 | 用 Vue 写 → 编译成小程序 + App + H5 | 用 Vue 语法，React 知识用不上 |

**本项目推荐：Taro。** 原因：团队已用 React，答题逻辑可直接复用，学习成本最低。

## 4. 改造工作量评估

| 模块 | 能否复用 | 说明 |
|---|---|---|
| 量表数据（题目/选项/计分键） | ✅ 完全复用 | `assets/data-core.js`、`assets/data-scl90.js` 是纯 JS 数据，直接拷贝 |
| 计分逻辑 | ✅ 完全复用 | `assets/app.js` 里的 `computeResult()` 是纯函数，与运行环境无关 |
| 页面结构（主页卡片 / 答题页 / 结果页） | ⚠️ 需重写 | 从 React `createElement` 改为 Taro 的 JSX 组件 |
| 样式（CSS） | ⚠️ 需适配 | 大部分 CSS 属性兼容，但需把 `px` 视觉稿换算为 `rpx`；自定义导航栏、安全区需单独处理 |
| 设计系统（animal-island-ui 规范） | ✅ 思路复用 | 颜色 token、圆角、3D 阴影等视觉规范可直接套用 |

**结论：约 50% 工作量在「界面重写 + 工程化搭建」，逻辑部分基本零成本迁移。**

## 5. 改造注意事项清单

### 5.1 账号与环境
- 需注册**微信小程序账号**（个人主体或企业主体），个人主体不能开通部分类目（如医疗健康类需资质）。
- 下载**微信开发者工具**，用 Taro 项目导入，真机预览需绑定测试号或已注册的 AppID。
- 发布前需**提交审核**，审核周期通常 1-7 天；`pages.wangyi.dpdns.org` 域名需在小程序后台配置为合法请求域名（若涉及线上接口）。

### 5.2 逻辑层复用
- `computeResult()`、量表数据结构直接搬入 Taro 项目，保持纯函数、无 DOM 依赖。
- 答题状态管理：Taro 支持 React Hooks（`useState`/`useRef`），当前 `assets/app.js` 的逻辑可平滑迁移。
- 建议先把**计分逻辑写成独立模块并写单元测试**，迁移后跑一遍 5 个量表的验证用例（如全选 1 分 → 粗分 50 / 标准分 62）。

### 5.3 界面层重写
- 网页用 `React.createElement`，Taro 用 **JSX**（`<View>`、`<Text>`、`<Button>` 组件），不能直接搬。
- 禁止在 Taro 里写 `document`、`window` 等浏览器对象；改用 Taro 提供的 API（如 `Taro.setStorage`）。
- 小程序没有 HTML 标签，`div` → `View`、`span` → `Text`，列表渲染用 `map` + `key`。

### 5.4 样式适配
- 尺寸单位：小程序推荐 **rpx**（750rpx = 屏幕宽度）。当前网页按 `px` 写的设计值（按钮高 45px、卡片圆角 20px 等）需换算：设计稿 375px 宽度下 1px ≈ 2rpx。
- 背景/渐变/阴影等 CSS 属性大部分支持，但 `position: fixed` 在小程序里有层级限制（用 `cover-view` 处理特殊场景）。
- 顶部导航栏建议使用**自定义导航**（`navigationStyle: custom`）以保留海岛风标题 ribbon，但需自己处理状态栏高度和左上角返回按钮。
- 适配 iPhone 底部安全区（`env(safe-area-inset-bottom)`）。

### 5.5 数据与本地存储
- 测试历史记录可用 `wx.setStorageSync` / `wx.getStorageSync`（对应网页的 `localStorage`），容量约 10MB。
- 不建议在小程序端保存敏感个人信息；如后续做账号体系，需接入微信登录（`wx.login` → code2session）。

### 5.6 包体积与性能
- 小程序主包限制 **2MB**，总体积上限 20MB（需用分包）。
- 当前 `assets/` 数据文件很小（SCL-90 约十几 KB），无需担心；但若后续加入图片/音效，注意体积。
- 90 题 SCL-90 的页面渲染性能：建议分题渲染（当前已是一题一页），避免一次性渲染 90 题。

### 5.7 分享与传播
- 小程序支持 `onShareAppMessage` 自定义分享卡片（标题 + 图片 + 路径），比网页分享体验好。
- 可针对每个量表设置不同分享文案，提升传播率。

### 5.8 隐私与合规（重点）
- 本项目属**心理健康自评**类内容，虽不涉及医疗诊断，但审核时需注意：
  - 页面需显著标注「结果仅供参考，不构成医学诊断」；
  - 避免出现「治疗」「诊断」「治愈」等医疗暗示词汇；
  - 若涉及用户输入的健康数据，需在小程序隐私协议中声明用途。
- 微信对「医疗健康」类目资质要求严格，建议以「心理测评工具/自测娱乐」方向提交，必要时咨询微信官方类目要求。

### 5.9 测试与发布
- 使用微信开发者工具的「真机调试」在 iPhone + Android 各测一遍（重点：进度条、选项点击、结果页滚动、安全区）。
- 提审前用「体验版」二维码发给自己/朋友走一遍完整答题流程。
- 发布后关注「小程序数据助手」看打开率、完成率，评估是否要优化题量或流程。

## 6. 建议的落地步骤

1. **评估**：确认小程序账号主体与类目可行性（尤其是健康类审核风险）。
2. **搭建工程**：用 Taro CLI 初始化 React 版本项目（`npx @tarojs/cli init`）。
3. **迁移数据与逻辑**：拷贝 `data-core.js` / `data-scl90.js` / `computeResult()`，补单元测试。
4. **重写页面**：主页（量表列表）→ 答题页 → 结果页，按 animal-island-ui 视觉规范用 WXSS 实现。
5. **本地/真机联调**：完成 5 个量表全流程。
6. **发布**：上传代码 → 提交审核 → 发布体验版/正式版。
