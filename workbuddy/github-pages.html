一句话说清

GitHub Pages 是 GitHub 提供的静态网站托管服务。 它直接读取你仓库里的文件，当成网站对外发布。 只要是「不需要后端程序」的东西 —— HTML、CSS、JavaScript、图片、博客 —— 它都能替你免费上线。

完全免费

公开仓库不限量，流量和存储都由 GitHub 承担。个人小站、作品集、文档站，一分钱不花。

三分钟上线

  1. 建一个仓库

    名称用 你的用户名.github.io，这是站点主域名仓库。 想放子站也可以随便建一个普通仓库，比如 my-site。

  2. 把网页文件放进去

    至少有一个 index.html，它是默认首页。子目录里的 html 也可以直接访问。

    # 目录结构示例
my-site/
├── index.html        # 首页
├── about.html        # 子页面 → /about.html
├── workbuddy/
│   └── index.html    # 子目录页 → /workbuddy/
└── style.css

  3. 开启 Pages

    仓库 Settings → Pages，Source 选分支（通常是 main）和目录 / (root)，保存。

  4. 等一分钟，打开链接

    形如 https://用户名.github.io/仓库名/；上一步的链接页面还会显示构建状态和实际地址。

提示 首次发布通常 1 分钟内完成。如果 404，先确认文件确实推送到了远端分支，再刷新 Pages 设置页看构建记录。

适合 / 不适合

维度说明
适合个人主页、作品集、项目文档、博客、演示 Demo、小游戏、说明书类静态页
不适合需要服务端逻辑的站点：登录注册、数据库读写、支付、文件上传、真实 API 后端
语言只有浏览器能跑的东西：HTML / CSS / JS / WASM / 图片 / 字体
构建可直接发布纯静态文件，也可接 Jekyll / Hugo / Hexo / Vite 等生成器的产物目录
使用限制软性限额约 1GB 站点、每月 100GB 流量、每小时 10 次构建；禁止商用或做纯下载站
私有仓库Free 账号需公开仓库才能用 Pages；Pro / 组织账号支持私有仓库发布
  • 想要后端？ 前端交给 Pages，接口另找 Serverless（如 Cloudflare Workers、云函数），两者拼起来就是一个完整产品。
  • 想要动态能力？ 用第三方 BaaS 或浏览器端存储顶一顶，冷启动阶段完全够用。

绑定自己的域名

在仓库根目录新建一个名为 CNAME 的文件（没有扩展名），里面只写一行域名：

# 文件名就叫 CNAME，内容只有一行
pages.example.com

然后到域名服务商加解析：

# 二级域名 → CNAME 记录
CNAME   pages   →   你的用户名.github.io

# 裸域名（example.com）→ A 记录，指向 GitHub 的四个 IP
A       @       →   185.199.108.153
A       @       →   185.199.109.153
A       @       →   185.199.110.153
A       @       →   185.199.111.153
提示 绑定域名后，Pages 设置里勾选 Enforce HTTPS，证书会自动签发。 根目录存在 CNAME 文件时，原 github.io 地址会自动跳转到你绑定的域名。

常见坑

  • 路径写错 —— 仓库站点发布在 /仓库名/ 下，用绝对路径 /style.css 会丢样式，推荐用相对路径 ./style.css 或 style.css。
  • 大小写敏感 —— 服务器区分大小写，Logo.png 写成了 logo.png 就是 404，本地 Windows 却看不见问题。
  • 想用下划线开头的目录 —— 老式 Jekyll 构建会忽略下划线目录，可在仓库根加一个空的 .nojekyll 文件绕过。
  • 改了不生效 —— 看 Actions / Pages 构建记录，别急着反复改代码；浏览器强刷或在链接后加参数排除缓存。
